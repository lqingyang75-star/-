# 实习生 AI Coding 全栈开发考核 — 改造方案

> 依据：《实习生AI Coding全栈开发实战考核》（20 页）
> 目标系统：后台权限管理 + 财务收支记账系统
> 数据库：MySQL 8
> 现有项目：d:\stock-picker（Spring Boot 3.3.5 / Java 21 / 原生单页前端）

---

## 0. 结论先行

**不新建工程，在现有 stock-picker 仓库上演进为公司化的后台系统。**

核心做法是三件事，不是推倒重来：

| # | 改造动作 | 说明 |
|---|---|---|
| 1 | 前端换栈 | 原生单页 → Vue 3 + Vite + Element Plus（考核硬性要求，必须换） |
| 2 | 后端加基座 | 在现有 Spring Boot 上补 MySQL + JPA + JWT + RBAC + 统一返回体 + 操作日志 |
| 3 | 业务加模块 | 新增「财务收支」核心得分模块；现有「选股」收敛为第三个业务模块保留 |

**为什么这样合理**：

- 后端骨架、Java 21、RESTful 接口经验直接复用，`pom.xml` 只需加依赖，不用重建工程
- 现有 `/api/stocks/*` 接口契约不变，Vue 版页面直接调用，不会打乱已验证的行情逻辑
- 选股模块保留下来，恰好能证明「动态菜单 + 权限隔离」对任意业务模块生效——答辩时是**架构通用性**的实证，而不是跑题的负担

**唯一需要接受的代价**：前端要重写一遍。这是考核的硬性技术栈要求，无法规避；但重写只发生在展示层，接口一行不改。

**答辩主线**：基础管理（RBAC）→ 财务收支 → 最后展示「接入第三个业务模块只需加一条菜单和一套接口」，收尾落在架构可扩展上。

## 1. 评分口径澄清

PPT 内部有两处不一致，需要按打分表（第 18 页）对齐，因为那是评委实际打分依据。

| 出处 | 表述 | 合计 |
|---|---|---|
| 第 6 页 | 基础 80 分 + 拓展 20 分 | 100 |
| 第 18 页（打分表） | 基础 50 + 额外维度 50 + 拓展 20（封顶 100） | 100（封顶） |

**实操结论**：基础必做部分实际权重 50 分，额外维度 50 分分量极重（一半的分不在写代码上）。拓展 20 分是叠加项，可用来补分。

## 2. 技术选型

### 2.1 前端（硬性要求 Vue，无选择空间）

| 项 | 选型 | 说明 |
|---|---|---|
| 框架 | Vue 3 + Vite | PPT 明确推荐 |
| UI 库 | Element Plus | 与后台管理场景最贴合，表格/表单/树/弹窗开箱即用 |
| 状态管理 | Pinia | Vue 3 官方推荐 |
| 路由 | Vue Router 4 | 需要 `addRoute` 动态注册，做动态菜单 |
| 请求 | Axios | 统一封装拦截器（带 token、401 自动登出） |
| 图表 | ECharts 5 | 拓展项 1 要求 |
| 构建 | Vite | 开发代理 `/api` 到后端 |

> 现有 index.html 是原生 HTML + 内联 JS 单文件，**完全不满足统一技术栈要求**，必须重做，不要试图复用。

### 2.2 后端

| 项 | 选型 | 说明 |
|---|---|---|
| 语言/框架 | Java 21 + Spring Boot 3.3.5 | 复用现有 pom 的版本 |
| 持久层 | Spring Data JPA (Hibernate 6) | 软删除用 `@SQLDelete` + `@SQLRestriction` |
| 数据库 | MySQL 8 | DECIMAL 支持好，演示正规 |
| 连接池 | HikariCP（默认） | 无需额外配置 |
| 认证 | JWT（jjwt 0.12.x，HS256） | 自研拦截器比完整 Spring Security 少踩坑 |
| 密码 | BCrypt（`spring-security-crypto` 单引） | 避免为 BCrypt 拖入整套 Security |
| Excel | 阿里 EasyExcel | 中文不乱码、流式写入 |
| 日志切面 | Spring AOP | 自动记录关键操作 |

**是否用 Spring Security**：考核不强制。自研 `HandlerInterceptor` + JWT 校验 + 自定义权限注解，代码量小、可控、答辩时讲得清。推荐这条路。

### 3.2 三个关键工程决策

**① 单 jar 部署，不拆两个服务**

Vite 的 `build.outDir` 直接指向 `src/main/resources/static`，构建后 `mvn spring-boot:run` 一条命令即可打开完整系统。答辩现场少一个进程、少一类故障点。

**② 前端路由用 hash 模式**

`createWebHashHistory()`。history 模式需要后端补 SPA fallback 转发，hash 模式完全不用配，稳定性优先。

**③ 选股模块的处理边界**

| 现有功能 | 处理方式 |
|---|---|
| `/api/stocks/pick`、`screen`、`compare`、`analyze` | **接口一行不改**，完整保留 |
| 「行情查询」页签 | 迁到 `views/stock/index.vue`，作为第三个业务菜单 |
| 「策略对比」「个股分析」 | 先用现有接口保留，视剩余精力决定是否迁到 Vue |
| 「赛车小游戏」 | **不进考核系统**，与评分无关，答辩讲它会分散注意力 |

原则：接口契约不动，只换展示层。这样即使前端迁移出问题，旧页面仍可回退对比。

## 4. 数据库设计（MySQL 8）

### 4.1 建表语句

```sql
CREATE DATABASE IF NOT EXISTS assess_finance
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
USE assess_finance;

-- ============ 基础管理：用户 ============
CREATE TABLE sys_user (
  id          BIGINT       NOT NULL AUTO_INCREMENT,
  username    VARCHAR(50)  NOT NULL COMMENT '登录账号',
  password    VARCHAR(100) NOT NULL COMMENT 'BCrypt 哈希，禁止明文',
  real_name   VARCHAR(50)  DEFAULT NULL COMMENT '姓名',
  status      TINYINT      NOT NULL DEFAULT 1 COMMENT '1启用 0禁用',
  created_at  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  is_deleted  TINYINT      NOT NULL DEFAULT 0 COMMENT '软删除标记',
  PRIMARY KEY (id),
  UNIQUE KEY uk_username (username)
) COMMENT='系统用户';

-- ============ 基础管理：角色 ============
CREATE TABLE sys_role (
  id          BIGINT      NOT NULL AUTO_INCREMENT,
  name        VARCHAR(50) NOT NULL COMMENT '角色名称',
  code        VARCHAR(50) NOT NULL COMMENT '角色标识 如 ADMIN',
  remark      VARCHAR(200) DEFAULT NULL,
  created_at  DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at  DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  is_deleted  TINYINT     NOT NULL DEFAULT 0,
  PRIMARY KEY (id),
  UNIQUE KEY uk_code (code)
) COMMENT='角色';

-- ============ 基础管理：菜单/按钮 ============
CREATE TABLE sys_menu (
  id          BIGINT      NOT NULL AUTO_INCREMENT,
  parent_id   BIGINT      NOT NULL DEFAULT 0 COMMENT '0 为一级',
  name        VARCHAR(50) NOT NULL COMMENT '菜单名称',
  type        TINYINT     NOT NULL COMMENT '1目录 2菜单 3按钮',
  path        VARCHAR(100) DEFAULT NULL COMMENT '路由路径',
  component   VARCHAR(120) DEFAULT NULL COMMENT '前端组件路径',
  perms       VARCHAR(100) DEFAULT NULL COMMENT '权限标识 如 fin:record:add',
  icon        VARCHAR(50)  DEFAULT NULL,
  sort        INT          NOT NULL DEFAULT 0,
  status      TINYINT     NOT NULL DEFAULT 1,
  created_at  DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at  DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  is_deleted  TINYINT     NOT NULL DEFAULT 0,
  PRIMARY KEY (id),
  KEY idx_parent (parent_id)
) COMMENT='菜单与按钮权限';

-- ============ 关联表 ============
CREATE TABLE sys_user_role (
  user_id BIGINT NOT NULL,
  role_id BIGINT NOT NULL,
  PRIMARY KEY (user_id, role_id)
) COMMENT='用户-角色';

CREATE TABLE sys_role_menu (
  role_id BIGINT NOT NULL,
  menu_id BIGINT NOT NULL,
  PRIMARY KEY (role_id, menu_id)
) COMMENT='角色-菜单（勾选即授权）';

-- ============ 财务：收支分类 ============
CREATE TABLE fin_category (
  id          BIGINT      NOT NULL AUTO_INCREMENT,
  user_id     BIGINT      NOT NULL COMMENT '归属用户，实现自定义分类',
  name        VARCHAR(50) NOT NULL,
  type        TINYINT     NOT NULL COMMENT '1收入 2支出',
  sort        INT         NOT NULL DEFAULT 0,
  created_at  DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at  DATETIME    NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  is_deleted  TINYINT     NOT NULL DEFAULT 0,
  PRIMARY KEY (id),
  KEY idx_user_type (user_id, type, is_deleted)
) COMMENT='收支分类';

-- ============ 财务：收支记录 ============
CREATE TABLE fin_record (
  id            BIGINT        NOT NULL AUTO_INCREMENT,
  user_id       BIGINT        NOT NULL COMMENT '自动关联当前登录用户',
  category_id   BIGINT        NOT NULL,
  type          TINYINT       NOT NULL COMMENT '1收入 2支出',
  amount        DECIMAL(14,2) NOT NULL COMMENT '记账金额，禁止用 DOUBLE',
  record_date   DATE          NOT NULL COMMENT '收支日期',
  remark        VARCHAR(255)  DEFAULT NULL,
  -- 以下为证券交易扩展字段，非交易记录时为空
  stock_code    VARCHAR(10)   DEFAULT NULL COMMENT '股票代码',
  trade_side    VARCHAR(4)    DEFAULT NULL COMMENT 'BUY 买入 / SELL 卖出',
  quantity      INT           DEFAULT NULL COMMENT '成交数量（股）',
  trade_price   DECIMAL(14,3) DEFAULT NULL COMMENT '成交价',
  commission    DECIMAL(14,2) DEFAULT NULL COMMENT '佣金',
  stamp_duty    DECIMAL(14,2) DEFAULT NULL COMMENT '印花税，仅卖出收取',
  transfer_fee  DECIMAL(14,2) DEFAULT NULL COMMENT '过户费',
  created_at    DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at    DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  is_deleted    TINYINT       NOT NULL DEFAULT 0,
  PRIMARY KEY (id),
  KEY idx_user_date (user_id, record_date, is_deleted),
  KEY idx_category (category_id),
  KEY idx_stock (user_id, stock_code)
) COMMENT='收支记录（含证券交易明细）';

-- 金额计算规则（后端 BigDecimal 计算，前端只展示）：
--   买入（type=2 支出）：amount = quantity * trade_price + commission + stamp_duty + transfer_fee
--   卖出（type=1 收入）：amount = quantity * trade_price - commission - stamp_duty - transfer_fee

-- ============ 操作日志 ============
CREATE TABLE sys_oper_log (
  id         BIGINT       NOT NULL AUTO_INCREMENT,
  user_id    BIGINT       DEFAULT NULL,
  username   VARCHAR(50)  DEFAULT NULL,
  module     VARCHAR(50)  DEFAULT NULL COMMENT '模块',
  type       VARCHAR(20)  DEFAULT NULL COMMENT '新增/修改/删除/导出',
  content    VARCHAR(500) DEFAULT NULL COMMENT '操作内容摘要',
  method     VARCHAR(200) DEFAULT NULL COMMENT '目标方法',
  ip         VARCHAR(50)  DEFAULT NULL,
  cost_ms    BIGINT       DEFAULT NULL,
  created_at DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  KEY idx_created (created_at)
) COMMENT='操作日志';
```

## 5. 接口清单（RESTful）

统一返回体：`{ "code": 0, "message": "ok", "data": ... }`，异常由 `GlobalExceptionHandler` 统一转 HTTP 4xx/5xx。

### 5.1 认证

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/login` | 账号密码登录，返回 `{token, userInfo, perms[], menuTree[]}` |
| GET | `/api/auth/me` | 获取当前登录人信息与权限码 |
| POST | `/api/auth/logout` | 登出（前端清 token） |

### 5.2 用户

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/users?page&size&keyword&status` | 分页 + 关键词 + 状态筛选 |
| POST | `/api/users` | 新增 |
| PUT | `/api/users/{id}` | 编辑 |
| DELETE | `/api/users/{id}` | 删除（软删） |
| PATCH | `/api/users/{id}/status` | 启用/禁用 |
| PATCH | `/api/users/{id}/password` | 重置密码 |

### 5.3 角色

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/roles?page&size&keyword` | 列表 |
| POST/PUT/DELETE | `/api/roles`、`/api/roles/{id}` | CRUD |
| GET | `/api/roles/{id}/menus` | 该角色已勾选菜单 id 集合 |
| PUT | `/api/roles/{id}/menus` | 保存角色菜单权限 |

### 5.4 菜单

|---|---|---|

### 5.7 统计

## 7. 核心实现要点

### 7.1 JWT 与自动登出

- 签发：登录成功生成 token，载荷含 `userId`、`username`，`exp` 设为 2 小时
- 校验：`JwtInterceptor` 拦截 `/api/**`（放行 `/api/auth/login`），解析失败或过期返回 401
- 前端：Axios 请求拦截器注入 `Authorization: Bearer <token>`；响应拦截器遇 401 → 清 token、清 Pinia → 跳 `/login`
- 路由守卫：无 token 访问受保护页面跳登录页（对应评分点「前端路由守卫」）

### 7.2 密码安全

`BCryptPasswordEncoder` 加密入库，登录时 `matches()` 比对。数据库里绝不出现明文。

### 7.3 动态菜单与 RBAC

1. 登录 → 按 `sys_user_role` 取角色 → 按 `sys_role_menu` 取菜单 → 组装树
2. 树里同时带出 `type=3` 的按钮权限码，平铺成 `perms[]` 一起返回
3. 前端把菜单树转成路由（`component` 字符串映射到 `import.meta.glob` 的组件），`router.addRoute` 注册
4. 侧边栏直接用菜单树渲染
5. 按钮级权限：`v-permission="'fin:record:add'"` 指令，无权限的按钮直接从 DOM 移除（不是 `display:none`，考核要求「杜绝无权限操作的按钮在界面上展示」）
6. 后端同步用 `@RequirePerm("fin:record:add")` + 切面校验，前后端双重保障

### 7.4 金额精度

- 数据库 `DECIMAL(14,2)`，Java 侧全程 `BigDecimal`
- 统计用 SQL `SUM(amount)` 返回 `BigDecimal`，再 `setScale(2, RoundingMode.HALF_UP)`
- **禁止** `double`/`float` 参与金额运算，这是评分点明确提到的「小数精度」

### 7.5 软删除

- 所有业务表带 `is_deleted`
- JPA：实体上 `@SQLDelete("UPDATE xxx SET is_deleted = 1 WHERE id = ?")` + `@SQLRestriction("is_deleted = 0")`，后续所有查询自动过滤
- 关联关系查询（如角色菜单）需手动加过滤条件

### 7.6 操作日志

自定义 `@OpLog(module="收支记录", type="新增")` 注解 + `@Around` 切面，自动记录操作人、时间、类型、方法、参数摘要、IP、耗时。加在增删改与导出的 Controller 方法上即可，避免手写重复代码。

### 7.7 Excel 导出

EasyExcel 写 `OutputStream`，`Content-Disposition` 用 `URLEncoder.encode(文件名, "UTF-8")` 处理中文；字段用 `@ExcelProperty` 标注中文表头；金额列设置数字格式保留两位小数。

### 7.8 多条件筛选

`range` 参数与 `startDate/endDate` 二选一：
- `today` / `week` / `month` → 后端换算成日期区间
- `custom` → 使用前端传入的 `startDate`、`endDate`
- 前端切换类型时必须清空 `categoryId`（分类区分收入/支出，跨类型残留会导致查空）

## 12. 风险提示

1. **选股模块只保留「接口 + 一个页面」**。别把策略对比、个股分析、赛车小游戏全部迁进新前端，那些不产生分数，还会拖长迁移时间。接口留着，页面按精力取舍。
2. **先做包结构收拢，再写新模块**。`stock/` 包不先归位，后面每加一个模块都会更乱，工程结构 10 分就悬了。
3. **不要跳过 OpenSpec 与 AI 对话记录**。这两项 20 分，纯文档，比多写两个加分功能更划算。
4. **动态菜单是最大技术难点**，建议在阶段一集中攻克，不要留到最后。
5. **AI 生成的代码必须自己读懂**。第 18 项 10 分是评委随机抽问，答不上来会直接影响「代码理解能力」评分。
6. **MySQL 8 连接信息不要硬编码进代码**，用 `application.yml` + 环境变量，答辩时切换演示环境更从容。
7. **前端目录不要提交构建产物到 git**，`src/main/resources/static` 下的 Vue 构建结果加进 `.gitignore`，答辩前重新 `npm run build` 一次即可。
